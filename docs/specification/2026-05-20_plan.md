# Dynamic Google Maps Opening Hours — Plan

**Date:** 2026-05-20
**Status:** Draft / not yet implemented
**Boutique Maps link:** https://maps.app.goo.gl/oCoF16yYMyiuR3Lz5

## Goal

Mirror the boutique's opening hours (including holiday overrides) from Google Business Profile to the website automatically, so the admin only needs to update hours in one place — Google — and the site reflects the change without a redeploy.

## Approach

Use the **Google Places API (New)** `Place Details` endpoint and read the `currentOpeningHours` field, which already includes holiday exceptions configured in Google Business Profile. Fetch server-side with caching, render on the page.

## Steps

1. **Google Cloud setup**
   - Create / reuse a Google Cloud project.
   - Enable the **Places API (New)**.
   - Create an API key, restrict it to server-side use (IP allowlist or referrer + HTTP restriction) and to the Places API only.
   - Store the key as `GOOGLE_PLACES_API_KEY` in the environment (Coolify / `.env.local`).

2. **Resolve the Place ID once**
   - Use Place Search (`places:searchText`) or the legacy `findplacefromtext` to look up the boutique by name + address.
   - Store the resulting Place ID as `GOOGLE_PLACE_ID` in the environment. This is a one-time lookup; the ID is stable.

3. **Server-side fetch with caching**
   - Endpoint: `GET https://places.googleapis.com/v1/places/{PLACE_ID}`
   - Headers:
     - `X-Goog-Api-Key: $GOOGLE_PLACES_API_KEY`
     - `X-Goog-FieldMask: currentOpeningHours,regularOpeningHours,utcOffsetMinutes`
     - `Accept-Language: hu` (or current locale) for Hungarian day names.
   - In Next.js: `fetch(url, { next: { revalidate: 3600 }, headers: {...} })` so hours refresh hourly without per-request cost.
   - Alternative: an on-demand revalidation route (`/api/revalidate-hours`) the admin can hit after editing Google Business Profile, for instant updates.

4. **Rendering**
   - Prefer `currentOpeningHours.weekdayDescriptions` — Google returns pre-formatted localized strings ("hétfő: 10:00–18:00").
   - For a custom table, iterate `currentOpeningHours.periods[]` (each has `open` and `close` with `day` + `hour` + `minute`).
   - Surface `specialDays` (holiday exceptions) inline or as a banner if today's hours differ from regular.

5. **Fallback**
   - If the API call fails (network, quota, key issue), render the last successfully cached hours. If no cache exists yet, render hardcoded fallback hours so the page is never empty.

## Tradeoffs

- **Cost:** Places API Details with the Opening Hours SKU is ~$5 / 1,000 requests after the free tier. With hourly revalidation: ~720 requests/month — well within free tier. Without caching: prohibitive.
- **Source-of-truth shift:** the admin must edit hours in **Google Business Profile**, not in code or a CMS. Workflow change to confirm before building.
- **Cache lag:** Google does not push updates. There is always a delay equal to the revalidate window (60 min default). On-demand revalidation route mitigates this.
- **API key exposure:** must remain server-side. Never expose to the browser. ISR / route handlers in Next.js handle this naturally.
- **Localization:** request with `Accept-Language` matching the active locale to get day names in the right language.

## Files likely to change

- `src/components/FindUs*` (or wherever current hardcoded hours live) — read from new data source instead of constants.
- New: `src/lib/google-places.ts` — fetch + parse helper.
- New (optional): `src/app/api/revalidate-hours/route.ts` — on-demand revalidation endpoint.
- `.env.local` / Coolify env — add `GOOGLE_PLACES_API_KEY`, `GOOGLE_PLACE_ID`.

## Out of scope

- Editing UI inside the site for hours (Google Business Profile is the editor).
- Multi-location support (single boutique only).
- Real-time push updates (Google does not provide webhooks for this).
